# ไอเดีย: ปุ่ม "ลบถาวร" สมาชิกที่ขาดเกินเกณฑ์

**สถานะ: ทำแล้ว** — แต่ออกแบบต่างจากแผนเดิม (ดู "ผลลัพธ์ที่ทำจริง" ท้ายไฟล์)

> **หมายเหตุภายหลัง (ระบบพักถูกถอดออกแล้ว)** — หลังจากงานนี้ หัวหน้ากิลด์สั่งเอา
> ระบบ "พัก" ทิ้งทั้งหมด: auto-bench, ปุ่ม "พักเลย", "คืนสถานะ", คอลัมน์
> `members.active` และ `DELETE /api/admin/members` ถูกลบออกทั้งย่อหน้านี้
> แท็บ "ไม่มา ไม่ลา" ยังอยู่ แต่เป็นรายการเตือนล้วน ไม่เขียนอะไรลงฐานข้อมูล
> **ภายหลังเพิ่มปุ่มถังขยะในแท็บนี้ เฉพาะแถวที่ขาดครบ `ABSENCE_ALERT_AFTER`**
> (เรียก route เดียวกับแท็บสมาชิก ไม่มีทางลบแบบอื่น) เพื่อไม่ให้ต้องไปหา
> ปุ่มในอีกแท็บ — รายละเอียดปุ่มในหัวข้อ 4 ด้านล่างยังใช้ได้
> แถว `active = 0` ที่เหลืออยู่ในฐานข้อมูลเดิมถูกลบทิ้งหนึ่งครั้งตอน cold start
> (`dropBenchedMembers` ใน `lib/db.ts`) ตัวอย่างด้านล่างจึงเป็นประวัติแล้ว

> สรุปที่ทำจริง: ปุ่ม **"พัก"** ในแท็บสมาชิกถูก **แทนที่** ด้วยปุ่มถังขยะ
> **"ลบออกจากกิลด์"** ที่ลบถาวร (ไม่ใช่เพิ่มปุ่มใหม่ข้าง ๆ) โผล่กับ**ทุกคน**
> รวมคนที่ถูกพักอยู่ และ**ลบประวัติ attendance ด้วย** — ยอมรับผลข้างเคียงข้อ ก.
> เพราะผู้ใช้ยืนยันว่า "ไม่เก็บข้อมูล" ส่วน auto-bench (`member-remove`) เคยอยู่
> เป็นเส้นทางเดียวที่ยังใช้คำว่า "พัก" และยังคืนได้ด้วย "คืนสถานะ"

---

ปัญหาที่ต้องการแก้: ตอนนี้มีแต่ "พัก" (`active = FALSE`) ซึ่งเก็บแถวและประวัติไว้
อยากได้ปุ่ม **ลบจริง** สำหรับสมาชิกที่หลุดจากกิลด์แล้วจริง ๆ — ไม่เป็นสมาชิกอีก
และไม่เก็บข้อมูล (ทั้งแถว roster และประวัติ attendance หายถาวร)

ต่างจาก "พัก" ที่ย้อนคืนได้ด้วยปุ่ม "คืนสถานะ" — ลบถาวร **ย้อนกลับไม่ได้**

## ขอบเขต

| เรื่อง | พัก (มีอยู่แล้ว) | ลบถาวร (งานนี้) |
| --- | --- | --- |
| แถวในแท็บ `members` | คงไว้ ตั้ง `active = FALSE` | **ลบแถวทิ้ง** |
| ประวัติในแท็บ `attendance` | คงไว้ครบ | **ลบทุกแถวของชื่อนั้น** |
| กลับคืน | ได้ ("คืนสถานะ") | **ไม่ได้** |
| โผล่ใน UI | แท็บสมาชิก (ขีดฆ่า) | ไม่โผล่ที่ไหนเลย |

เกณฑ์ที่จุดปุ่ม: **ขาดเกิน 2 ครั้ง** = `count >= 3` = `BENCH_AFTER_ABSENCES`
(ดู `lib/rngw/attendance.ts`) — เกณฑ์เดียวกับที่ auto-bench ใช้อยู่แล้ว

## กับดักที่ต้องรู้ก่อนทำ

### ก. ลบแถว attendance ไปเปลี่ยนตัวเลขขาดของ "คนอื่น"

การนับขาดของทุกคนพึ่งเงื่อนไข "วันนั้นต้องมีคนตอบจริง" ซึ่งดึงจากแถว attendance
ทั้งแท็บ (`playDays` ใน `absencesFor`) ถ้าคนที่ถูกลบเคยเป็น**คนเดียวที่ตอบในวันนั้น**
พอลบแถวหมด วันนั้นจะไม่นับว่าเล่นอีก → จำนวนขาดของเพื่อนคนอื่น **ลดลงเงียบ ๆ**
อาจมีคนหลุดจากเกณฑ์พักโดยไม่ตั้งใจ

ต้องตัดสินใจ: ยอมรับผลนี้ หรือเก็บแถว attendance ไว้ (ขัดกับ "ไม่เก็บข้อมูล")

### ข. attendance เป็น append-only เพื่อกันเขียนชนกัน

การลบแถวคือ read-modify-write ตัวแรกบนแท็บนี้ ถ้าลบตอนสมาชิกกำลังกดเช็คชื่อพอดี
อาจมีจังหวะชนกันได้ (แอดมินทำคนเดียว ความเสี่ยงต่ำ แต่ควรรู้ไว้)

### ค. ลบหลายแถวในแท็บเดียวต้องลบจากล่างขึ้นบน

`deleteRows` เปลี่ยน index ของแถวถัดไป ถ้าเก็บ row number ตอนหาแล้วลบไล่จากบน
แถวจะเลื่อนทำให้ลบผิดคน ต้องเรียงจากมากไปน้อย

### ง. เกณฑ์ซ้ำกับ auto-bench

auto-bench พักคนที่ครบ 3 ให้เองอยู่แล้วตอนเปิดแท็บ "ไม่มาไม่ลา" ถ้าเพิ่มปุ่มลบที่
เกณฑ์เดียวกัน อาจไม่ทันได้กดเลยเพราะระบบพักไปก่อน ต้องตัดสินใจว่าจะ:
- เอา auto-bench ออก แล้วให้แอดมินกดลบ/พักเอง, หรือ
- คง auto-bench ไว้ (ปุ่มลบจะเป็นทางเลือกหลังถูกพักแล้ว)

## แผนงาน

### 1. `scripts/google-apps-script/Code.gs`

- เพิ่ม action `member-delete` ใน `doPost` (ต่อจาก `member-remove` บรรทัด ~370)
  ต้องผ่าน `checkPin` เหมือน action ที่เขียนข้อมูลตัวอื่น (บล็อกอยู่แล้วเพราะ
  `action !== "attendance"`)
- ฟังก์ชัน `deleteMemberRow(payload)`:
  1. หา row ใน `members` ด้วย `findRow(sheet, name, 1)` — ถ้าไม่เจอคืน 404
  2. `deleteRow` แถวนั้น
  3. หาทุก row ใน `attendance` ที่คอลัมน์ name ตรง แล้ว `deleteRows` **จากล่างขึ้นบน**
  4. คืน `{ ok: true, deleted: <จำนวนแถว attendance ที่ลบ> }` เพื่อรายงานผล
- ใช้ `clean(payload.name, 40)` เหมือนเดิม

แก้ `Code.gs` แล้วใช้ทันที ไม่ต้อง redeploy (Web App รันในชื่อเจ้าของสคริปต์)
แต่ **deployment เก่าที่ยังไม่มี action นี้จะตอบ "unknown action"** — ถ้า API ฝั่ง
Next.js เรียกแล้วเจอ error นี้ ให้บอกให้ redeploy

### 2. `lib/sheets.ts`

- เพิ่ม `deleteMember(name, pin)` เรียก `call({ action: "member-delete", pin, name })`
  ผ่าน `unwrap` เหมือน `benchMember` (บรรทัด ~269)
- คง `benchMember` ไว้คู่กัน อย่ายุบรวม เพราะความหมายต่างกันคนละเรื่อง

### 3. API — แยก route ให้ชัด อย่ายัดรวมปุ่มเดิม

`DELETE /api/admin/members` (บรรทัด ~51) **ยังต้องหมายถึง "พัก" เหมือนเดิม**
ไม่แตะ เพื่อไม่ให้ปุ่มเก่าเปลี่ยนพฤติกรรมเงียบ ๆ

เพิ่ม route ใหม่ `app/api/admin/members/purge/route.ts`:
- `POST` รับ `{ name }`
- `requireAdmin()` ก่อนทุกครั้ง
- เรียก `deleteMember(name, await readAdminPin())` — PIN ถูกตรวจซ้ำที่ Apps Script
- ตอบ `{ ok, deleted }` ให้ toast รายงานจำนวนแถวที่ลบ

ทางเลือกอื่นที่พิจารณาแล้วตกรอบ: ใช้ `DELETE /api/admin/members?hard=1` — ตกเพราะ
ปุ่มทำลายข้อมูลควรมี URL ของตัวเอง อ่าน audit log แล้วรู้ทันทีว่าลบถาวร

### 4. UI — `components/admin/member-manager.tsx`

- เพิ่มปุ่ม **"ลบถาวร"** แยกจากปุ่มถังขยะ "พัก" เดิม (บรรทัด ~349)
  - โผล่เฉพาะสมาชิกที่ `absences.get(name).count >= BENCH_AFTER_ABSENCES`
    (ขาดเกิน 2) เพื่อไม่ให้เผลอลบคนที่ยังไม่เข้าเกณฑ์ — ตรงกับที่ต้องการ
  - ใช้ไอคอนคนละตัวกับ `UserMinus` (เช่น `Trash2`) และสีแดง
- ปุ่มต้องผ่าน `useConfirm` **tone: "danger"** และ `description` ต้องบอก**ผลที่ตามมา
  และจำนวนที่กระทบ** ไม่ใช่แค่ "แน่ใจไหม" — ตามกฎ AGENTS.md
  ตัวอย่าง: "ลบ <ชื่อ> ออกจากกิลด์และลบประวัติการเช็คชื่อ <N> แถวถาวร คืนไม่ได้"
  (N มาจาก `attendance` ที่กรองชื่อนั้น — คำนวณฝั่ง client ได้ มีข้อมูลอยู่แล้ว)
- สำเร็จ → `toast.success` · ล้มเหลว → `toast.error` เก็บข้อความจริงจาก API
- เรียก `onSaved()` ให้ panel refetch
- **ต้อง render `{confirmDialog}`** ใน JSX (มีอยู่แล้วใน component นี้)

### 5. ความสอดคล้องกับ "ไม่มาไม่ลา"

หลังลบถาวร สมาชิกหายจาก `absencesFor()` เองอยู่แล้ว (ไม่มีใน `members`) จึงไม่โชว์
ที่ไหน — ไม่ต้องแก้ตรรกะการนับ

ถ้าภายหลังอยากให้คนที่ถูก**พัก**ยังเห็นในตาราง warnings (ตอนนี้เป็น dead code ที่
`if (!member.active) continue` ตัดออก) ต้องแก้ `absencesFor` แยก — ไม่อยู่ในงานนี้

### 6. เอกสาร

- อัปเดต `AGENTS.md` ตารางบทบาทและสิทธิ์: แถว "เพิ่ม/แก้/พักสมาชิก" → เพิ่ม
  "ลบถาวร (ขาดเกิน 2)" ให้ชัดว่าต้อง PIN และย้อนไม่ได้
- ถ้ามีหัวข้อ "ยืนยัน และแจ้งผล" อยู่แล้ว ไม่ต้องแก้ แค่ทำตาม

## ประเด็นที่ต้องตัดสินใจก่อนลงมือ

1. **ลบประวัติ attendance ด้วยไหม?** ผู้ใช้ระบุว่า "ไม่เก็บข้อมูลด้วย" แต่มีผลข้างเคียง
   ข้อ ก. (ตัวเลขขาดของคนอื่นเพี้ยน) — ถ้าไม่อยากให้เพี้ยน ทางเลือกคือไม่ลบแถว
   attendance (ขัดเจตนา) หรือเก็บแถวที่ลบลงแท็บใหม่ เช่น `attendance-deleted`
2. **auto-bench ยังอยู่ไหม?** ถ้าอยากให้แอดมินเป็นคนตัดสินใจลบเอง อาจต้องปิด auto-bench
3. **ต้องพิมพ์ชื่อยืนยันไหม?** กรณีลบทั้งคน + ประวัติ อาจให้พิมพ์ชื่อสมาชิกเพื่อกันกดพลาด
   (แรงกว่า confirm ปุ่มเดียว แต่ช้ากว่า)

## การทดสอบ (mock ก่อน ไม่แตะชีตจริง)

- เช็คก่อนว่าปุ่มโผล่เฉพาะคนที่ขาดเกิน 2 (`count >= BENCH_AFTER_ABSENCES`) — คนที่ยัง
  ไม่เข้าเกณฑ์ต้องไม่เห็นปุ่มนี้เลย
- ทดสอบจริงกับชีตสำรองก่อนเสมอ เพราะลบแล้วย้อนไม่ได้:
  1. เพิ่มสมาชิกทดสอบ 1 คน + attendance 2–3 แถว
  2. กดลบถาวร → เช็คว่าแถวหายทั้ง `members` และ `attendance`
  3. เช็คว่าเพื่อนร่วมวันไม่ได้รับผลกระทบ (ข้อ ก.)
- เช็คบนมือถือ 320px ว่าปุ่มลบกับปุ่มพักกดไม่โดนกัน (ปุ่มทำลายควรแยกให้ชัด)
