# ไอเดีย: ย้ายค่าตั้งค่าจาก env เข้าหน้าแอดมิน

**สถานะ: ยังไม่ได้ทำ** — เขียนเก็บไว้ก่อน เพื่อให้ตัดสินใจทันทีว่าจะทำหรือไม่

ปัญหาที่ต้องการแก้: เวลาสร้าง Apps Script deployment ใหม่ URL เปลี่ยน ต้องไปแก้
`GOOGLE_APPS_SCRIPT_URL` ใน Vercel แล้ว redeploy ทุกครั้ง อยากให้แก้จากหน้าเว็บได้

## ขอบเขต — อะไรย้ายได้ อะไรไม่ได้

| ตัวแปร | ย้ายได้? | เหตุผล |
| --- | --- | --- |
| `GOOGLE_APPS_SCRIPT_URL` | ✅ | เป้าหมายหลักของงานนี้ |
| `GUILD_TIMEZONE` | ✅ | เป็นข้อมูลธรรมดา ไม่กระทบความปลอดภัย |
| `GUILD_PIN` | ❌ | วนกันเอง — หน้า login ต้องเช็ค PIN ก่อนจะมีสิทธิ์แอดมิน ถ้าย้ายไปเก็บในที่ที่หน้า login อ่านได้ จะไม่มีทางเข้า |
| `SESSION_SECRET` | ❌ | ใช้เซ็น cookie (lib/auth.ts) ถ้าหน้าเว็บอ่านได้ ใครก็ forge cookie เป็นแอดมินเองได้ |

หลังงานนี้ env จะเหลือแค่ `GUILD_PIN` + `SESSION_SECRET`

## ปัญหาที่ต้องระวัง — วงกลมก้อนหนอน

เวลาคิดครั้งแรกดูเหมือนทำไม่ได้ เพราะเก็บ URL ไว้ในชีตก็ต้องอ่านชีตก่อน
แต่การอ่านชีตก็คือการเรียก URL ที่ยังไม่รู้ → วงกลมก้อนหนอน และถ้า URL ใน env ตาย
หน้าตั้งค่าจะเปิดไม่ได้ ก็แปลว่าบันทึก URL ใหม่ไม่ได้

**สิ่งที่ทำให้มันออก: deployment เก่าของ Apps Script ไม่ตาย** ตอนกด
Deploy → New deployment URL เก่ายังรันอยู่ ดังนั้น:

1. URL เก่าใน env ยังใช้ได้ → login ได้
   (หน้า login เช็ค PIN กับ env ล้วน ๆ ไม่แตะชีต — `app/api/admin/login/route.ts`)
2. เปิดแท็บ "ตั้งค่า" → วาง URL ใหม่ → บันทึกลงชีต
3. จบ ไม่ต้องแตะ Vercel

เคสที่ช่วยไม่ได้คือ URL ตายจริง ๆ (deployment ถูกลบ / บัญชีหลุดสิทธิ์)
แต่กรณีนั้น env ยังทำหน้าที่เป็นทางหนีได้อยู่ดี

## ทางเลือกที่พิจารณาแล้วตกรอบ

- **เก็บในไฟล์ JSON ของโปรเจกต์** — ตก เพราะ deploy บน Vercel แบบ serverless
  ไฟล์หายทุกครั้งที่ deploy ใหม่
- **Vercel KV / Edge Config** — ไม่จำเป็นแล้ว เพราะข้อ 1 ข้างบนแก้ปัญหาวงกลมได้
  แลกกับ dependency + ค่าใช้จ่าย + round trip ทุกครั้งที่อ่านชีต ถ้าวันหนึ่งต้องทำ
  ให้แก้ URL ได้แม้ deployment เก่าตายจริงค่อยพิจารณา

## แผนงาน

### 1. `Code.gs`

- เพิ่ม `SETTINGS_TAB = "settings"` กับ `SETTINGS_HEADER = ["key", "value"]`
- `setup()` สร้างแท็บนี้เพิ่ม (ถ้ายังไม่มี)
- `doGet` คืน `settings` มาด้วย **ในคำขอเดียวกัน** — ไม่เพิ่ม round trip
  เพราะ consumer Apps Script รันได้ทีละ execution ยิ่งหลายคำขอยิ่งเข้าคิว
- เพิ่ม action `settings-save` (ต้อง PIN เหมือน action อื่นที่เขียนข้อมูล)
- อ่านแท็บ settings ต้องทนทานกว่าแท็บอื่น — ถ้ายังไม่ได้สร้างแท็บให้คืนค่าว่าง
  ไม่ใช่ throw ไม่งั้น `doGet` พังหมด

แก้ `Code.gs` แล้วใช้ทันที ไม่ต้อง redeploy (Web App รันในชื่อเจ้าของสคริปต์)

### 2. `lib/settings.ts` (ใหม่)

ตัดสิน URL ตามลำดับนี้

1. ค่าที่เคยอ่านได้ล่าสุด (cache ระดับโมดูล) — เร็วที่สุด
2. ค่าใน env `GOOGLE_APPS_SCRIPT_URL` — ทางหนีตอนแรก
3. ถ้าข้อ 1 หรือ 2 ล้ม และอีกตัวยังใช้ได้ → ลองอีกตัวหนึ่ง แล้วจำผลไว้
   เพื่อไม่ให้คำขอทุกครั้งเสียเวลารอ timeout

ค่าใน settings ที่อ่านได้ต้อง validate ก่อนใช้ (ต้องลงท้าย `/macros/s/`) เหมือนที่
`endpoint()` เช็คอยู่ตอนนี้ ไม่งั้นค่าผิดในชีตจะทำให้ทั้งเว็บล่ม

### 3. API

- `GET /api/admin/settings` — คืนค่าปัจจุบัน (ผ่าน `requireAdmin()`)
- `POST /api/admin/settings` — บันทึก + ส่ง PIN ไปให้สคริปต์ตรวจซ้ำ
  เหมือนที่ `saveMember` / `saveParties` ทำอยู่แล้ว

**URL เป็น capability URL** — คนที่มีมันอ่านชีตได้ และส่ง attendance ได้ ตอนนี้มันอยู่ใน env
ที่ไม่รั่วถึงคนอื่น จะไม่ส่งไปหน้าปกติ มีแต่ endpoint ที่ผ่าน `requireAdmin()` เท่านั้น

### 4. UI — แท็บ "ตั้งค่า" ในหน้าแอดมิน

ช่อง URL ของ Apps Script + เวลาโลก ปุ่มบันทึก

**จุดที่ต้องแก้ให้ดี — จุดที่งานนี้พังง่ายที่สุด**

`components/admin/admin-panel.tsx:165` เรนเดอร์ `<Tabs>` **ต่อเมื่อ `data` โหลดสำเร็จเท่านั้น**
แปลว่าถ้าชีตอ่านไม่ได้ (URL เพี้ยน ซึ่งคือเคสที่ต้องเข้ามาแก้ URL พอดี)
หน้าแอดมินจะไม่มีแท็บให้เข้าไปแก้ → ต้องแยกแท็บตั้งค่าออกมาให้โผล่ได้เสมอ
พร้อม banner บอกว่าข้อมูลหลักโหลดไม่ได้

### 5. เอกสาร

- อัปเดต `.env.example` — `GOOGLE_APPS_SCRIPT_URL` เป็นตัวเลือก (ค่าสำรอง/ค่าเริ่มต้น)
  ลบ `GUILD_TIMEZONE`
- อัปเดต `docs/google-sheets-setup.md` ขั้นตอนที่ 5 ที่บอกให้ก๊อป URL ไปใน `.env.local`
- อัปเดต `AGENTS.md` หัวข้อบทบาทและสิทธิ์ ให้มีบรรทัดว่า "แก้ค่าตั้งค่าได้ที่หน้าแอดมิน"

## ข้อควรระวัง

- Apps Script รันได้ทีละ execution ต่อบัญชี — อย่าเพิ่มการเรียกสคริปต์เป็นรอบแยก
  ทุกอย่างที่อ่านพร้อมกันให้อยู่ใน `doGet` คำขอเดียว
- ค่าใน settings เป็นข้อมูลที่สคริปต์เขียนได้ ต้อง validate ทุกครั้งที่ใช้ ไม่เชื่อค่าดิบ
- หน้า settings ต้องโหลดได้แม้ชีตล่ม (ข้อ 4) ไม่งั้นฟีเจอร์นี้กู้ตัวเองไม่ได้
